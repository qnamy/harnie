# Harness Digest (Run 텔레메트리 → 하네스 개선 제안)

quality-digest의 원칙 — 반복 근거를 클러스터링하고, 승격을 제안하되, 아무것도 자동으로 바꾸지 않는다 — 를 **하네스 자신**에 적용한다. 입력은 완료된 harnie:dev run 1개 이상, 출력은 사용자가 채택/기각하는 순위화된 제안 목록이다. 각 run의 실측된 낭비를 자기수정-하네스 리스크 없이 다음 버전의 계약으로 바꾸는 메커니즘이다: **이 스킬은 어떤 파일도 쓰지 않고 어떤 설정도 바꾸지 않는다.**

## 입력 (전부 기존 산출물, 새 계측 없음)

sanctioned 경로로만 읽는다(Read 도구; 셸이 필요한 것은 `loop.mjs export`):

- `execution.json` — 태스크별 시각, `codexCalls`, `watchdogExtensions`, `threadRebindings`.
- 리뷰 유닛 상태 — 각 `review/<unit>/ledger.json` + `state.json`(라운드 수·blocking 이슈 추이), 각 태스크의 `review-archive/t<id>/`(통합 시 아카이브된 유닛 리뷰).
- 델타 사이드카(각 `delta.patch` 옆의 `*.json`) — 라운드별 `changedCount`: 유닛의 실제 크기.
- `design/errata.md`(`errata-list` 출력) — 승인 설계가 틀렸던 지점.
- `notepad.md` — 기록된 경로 선택(직렬 경로 근거), 인계, 인시던트 기록.
- 선택: 호출자가 제공하는 세션 JSONL 토큰 통계(콜당 입력 크기, 캐시 리드).

## 절차

1. **유닛 비용 프로파일.** 리뷰 유닛마다: 라운드 수 × changedCount × 모델 티어(+watchdog 연장, 리바인딩). 평균이 아니라 분포의 이상치를 표시한다.
2. **이상 클러스터링.** 찾아야 할 낭비 유형: 풀 루프를 지불한 극소 유닛(파일 수·changedCount 낮음); 유닛을 가로질러 반복되는 동일 발견 클래스(기준 공백); 한 유닛 3라운드 이상(설계 섹션·브리프 결함); 반복 watchdog 연장(예산 오티어링); 어느 run에서도 발화하지 않은 지침·게이트(정리 후보); 병렬 가능 태스크에서 근거 기록 없는 직렬 경로 선택.
3. **제안.** 클러스터마다: `{ 근거(run/유닛/수치) · 제안 변경(지침 문구/manifest 규칙/모델 티어/granularity 가이드) · 예상 절감 · 리스크 — "불변식 저촉" 라벨 명시 포함 }`. 규칙을 정리·완화하는 제안은 run을 가로지른 rule of three, fail-fast를 추가하는 제안은 중대 인시던트 1건이면 충분하다.
4. **사람 게이트.** 목록을 제시하고 사용자가 고른다. 채택된 변경은 일반 개발 플로우를 거친다(하네스 코드·문서 변경도 다른 변경과 같다) — 이 스킬이 적용하는 일은 없다.

## 하드 가드

- 사고 유래 불변식(`docs/enforcement-map.md`의 "문서만 있는 규범" 목록, 0.10 설계의 NFR4 불변식)을 제거·완화하는 제안도 **표시는 하되** 반드시 `불변식 저촉` 라벨을 단다 — 사람이 판단하고, 스킬은 조용히 버리지도 채택하지도 않는다.
- 강제 비용을 정직하게 보고한다: 토큰을 아끼지만 사용자 게이트나 엔진 표면을 늘리는 제안은 그렇다고 말해야 한다.
- 파일 쓰기·설정 변경·상태 변경 없음 — 분석과 제안만.

## 출력

순위화된 제안 목록(절감/리스크 비율 높은 순), 각 항목은 근거 포함 자기완결 + 수치를 검증할 수 있는 run 요약 표 1개(유닛·라운드·이상치). 두 run 비교(예: 하네스 버전 전/후)일 때는 회귀 체크를 앞세운다: 콜당 입력 p50, 임계 경로 대비 wall time, 사용자 게이트 횟수.
