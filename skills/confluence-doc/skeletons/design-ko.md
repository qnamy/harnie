# 스켈레톤 — 설계 문서 (아키텍처 / 상세)

이것은 `confluence-doc` 엔진이 로드하는 **설계 문서 섹션 스켈레톤**이다. 스킬 본문(`SKILL.md`)이 렌더링, 다이어그램 처리, 발행 규칙을 소유한다. 이 파일은 **섹션 구조와 상대적 비중만** 정의한다.

최종 Confluence 문서는 **한국어로** 렌더링한다. 이 스켈레톤의 영어 라벨과 산문은 구조만 서술한다. 생성되는 섹션 헤딩, 라벨, 표, 패널, 설명 텍스트는 한국어로 번역하되 식별자와 인용된 원문은 보존한다.

## 문서 유형별 비중 (가변 깊이)

스켈레톤은 하나를 쓰되, 문서 유형에 따라 세부 사항을 다르게 집중한다.

- **아키텍처 설계 문서** → §3과 §4(구조와 핵심 결정)에 집중한다. §5는 얕게 둔다.
- **상세 설계 문서** → §5와 §6(계약과 실패 처리)에 집중한다. §3은 짧고 참조 위주로 둔다.

모든 섹션을 고르게 채우지 않는다. 위험이나 변경 비용이 가장 큰 서너 곳에서 다섯 곳까지 세부 사항을 집중시키고, 나머지는 의도적으로 짧게 둔다.

## 섹션 스켈레톤

```
[상단 요약 패널]  ← 끝까지 스크롤하지 않을 다른 팀(PM, QA, FE)을 위한 것. panel-info. (공통; SKILL.md 렌더링 규칙 참조)
  상태 · 작성자 · 리뷰어 · 마감일 | 대상 독자 | 한 줄 목적 | TL;DR (핵심 결론 세 가지) | 관련 링크
1. 개요             — 배경과 목적, 범위(In-Scope / Out-of-Scope), 비목표
2. 요구사항         — FR/NFR (ID 보존; 정량화된 NFR만 포함) · 표
3. 아키텍처와 데이터 흐름 — 컴포넌트 표 + 데이터-흐름 단계 표 (+ 유용하면 ASCII 토폴로지)
4. 핵심 결정과 트레이드오프 — 맥락 · 결정 · 대안 비교 표 · 영향 · 재검토 조건
5. 데이터 모델과 API/이벤트 계약 — 표. 기계가 읽을 수 있는 스키마가 있으면 그 경로와 ID만 "계약의 단일 진실 공급원"으로 참조
6. 제약, 실패 모드, 예외 처리 — 엣지 케이스 · 재시도/DLQ · 다른 팀이 알아야 할 것  ← panel-warning
7. 리스크와 미해결 결정 — [미결정] (`undecided`) · 결정 시한 (decision-list)
```

## 섹션 근거 (참조 매핑)

- **상단 요약 패널** ← Google Technical Writing(대상 독자, 범위, 핵심 결론을 앞에 둔다) + Atlassian DACI(상태, 담당자, 마감일, 결과를 위에 둔다). 다른 부서는 끝까지 읽지 않는다.
- **§4 핵심 결정과 트레이드오프** ← AWS ADR(맥락 → 결정 → 결과, 검토한 대안, 재검토 조건). 대안을 비교하기 전에 결론을 신호하지 않는다.
- **문서 유형(설계/정의/제안)을 분리** ← GitLab의 문서 유형 분리 원칙. 이것이 스켈레톤을 유형별로 나누는 이유다.

## 매핑 노트 (상위 방법론 → 이 스켈레톤)

상위 `software-design` 스킬의 산출물(대상·범위·비범위 / 결정 / 변경 대상 / 데이터·상태 / 실패 동작 / 검증 / 가정·미결정 / 대안 비교)을 개념별로 위 일곱 섹션에 접어 넣는다.

- 1절 대상·범위·비범위 → 상단 요약 패널 + §1
- 설계가 인용하는 요구사항 파일(기능 요구·품질 제약) → §2. 설계는 요구사항을 다시 쓰지 않으므로 그 파일에서 가져온다. 파일이 없으면 설계가 지정한 요청에서 가져온다
- 3절 변경 대상 (파일, 인터페이스, 건드리면 안 되는 것) → §3
- 2절 결정 + 8절 대안 비교 → §4
- 4절 데이터·상태 → §5
- 5절 실패 동작 + 6절 검증 → §6. 검증을 독립된 표 — 명령 · 통과 조건 · 그대로 유지되어야 할 것 — 로 옮겨 완료를 어떻게 관측하는지 독자가 볼 수 있게 한다
- 7절 가정·미결정 → §7 (`[가정]`은 assumptions로, `[미결정]`은 결정권자와 막힌 범위를 담은 undecided로)

상위의 **Mermaid 다이어그램(C4 Container, 시퀀스, 상태)**은 `SKILL.md`의 다이어그램-렌더링 규칙에 따라 처리한다. Mermaid 매크로**와** 호환되는 발행 어댑터가 모두 있으면 네이티브로 렌더링하고(모드 A), 그렇지 않으면 표/ASCII로 강등하고 Expand 안에 소스를 보존한다(모드 B).
