# 골격 — 설계서 (아키텍처 / 상세)

`confluence-doc` 엔진이 로드하는 **설계서 섹션 골격**이다. 렌더링·강등·발행 규칙은 스킬 본체(`SKILL.md`)가 소유한다. 여기서는 **섹션 구성과 강약만** 정의한다.

최종 Confluence 문서는 **한국어로 작성한다.** 섹션 제목·라벨·표·패널·설명문은 한국어로 작성하고, 식별자와 인용 원문은 원래 표기를 유지한다.

## 종류별 강약 (깊이 차등)

하나의 골격을 쓰되 문서 종류에 따라 분량을 집중한다.
- **아키텍처 설계서** → §3·§4(구조·핵심 결정)에 집중, §5는 얕게.
- **상세 설계서** → §5·§6(계약·실패 처리)에 집중, §3은 참조로 짧게.

모든 섹션을 균등하게 채우지 않는다. 위험·변경비용이 큰 3~5개에 분량을 몰고, 나머지는 의도적으로 짧게.

## 섹션 골격

```
[상단 요약 패널]  ← 스크롤 안 내리는 타 팀(PM·QA·FE)용. panel-info. (공통 — SKILL.md 렌더링 규칙)
  상태 · 작성자 · 리뷰어 · 기한 | 대상 독자 | 한 줄 목적 | TL;DR(핵심 결론 3줄) | 관련 링크
1. 개요            — 배경·목적, 범위(In-Scope / Out-of-Scope), 비목표
2. 요구사항         — FR/NFR (ID 보존, NFR은 수치화된 것만) · 표
3. 아키텍처·데이터 흐름 — 컴포넌트 표 + 데이터 흐름 단계 표 (+ 필요시 ASCII 위상도)
4. 핵심 결정·트레이드오프 — 맥락 · 결정 · 대안 비교 표 · 영향 · 재검토 조건
5. 데이터 모델·API/이벤트 계약 — 표. 기계 스키마가 있으면 "계약 단일출처"로 경로·ID만 참조
6. 제약·실패 모드·예외 처리 — 엣지케이스 · retry/DLQ · 타 팀이 알아야 할 것  ← panel-warning
7. 리스크·미결정      — [미결정] · 결정 기한 (decision-list)
```

## 섹션 근거 (레퍼런스 매핑)

- **상단 요약 패널** ← Google Technical Writing(대상 독자·범위·핵심 결론을 문서 앞에) + Atlassian DACI(상태·책임자·기한·결과를 상단에). 타 부서는 스크롤을 끝까지 내리지 않는다.
- **§4 핵심 결정·트레이드오프** ← AWS ADR(맥락 → 결정 → 영향, 검토한 대안·재검토 조건). 대안 비교 전 결론을 선암시하지 않는다.
- **문서 종류 분리(설계서/정의서/제안서)** ← GitLab 문서 유형 분리 원칙. 골격을 종류별로 나눈 이유.

## 매핑 노트 (상류 방법론 → 이 골격)

상류 `instructions/design-authoring-arch.md`(경량: Executive Summary/목표·범위/요구사항/대안 비교/권장 아키텍처/핵심 시나리오/리스크)와 `instructions/design-authoring-detail.md`(경량: 설계 요약/요구사항 추적표/핵심 처리 로직/계약/데이터·상태/작업 분해/미결정)의 산출물을 위 7섹션으로 접는다:

- Executive Summary / 설계 요약 → 상단 요약 패널 + §1
- 요구사항(FR/NFR) / 추적표 → §2
- 권장 아키텍처 · 컴포넌트 내부 구조 · 핵심 시나리오 → §3
- 아키텍처 대안 비교 · ADR → §4
- 데이터 아키텍처 · API/이벤트 계약 · DB 상세 → §5
- 실패 처리 · 오류 규약 · 제약 → §6
- 리스크·미결정 → §7

상류의 **Mermaid 다이어그램(C4 Container·sequence·state)은 SKILL.md의 강등 규칙**에 따라 표/ASCII + Expand 소스로 변환한다.
