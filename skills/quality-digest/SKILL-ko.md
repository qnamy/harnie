# 품질 다이제스트 (반복 지적 → 강제 규칙 제안)

일정 기간 누적된 리뷰 지적을 모아 **반복되는 품질 문제**를 찾고, 각각을 **강제 규칙으로 승격할 후보**를 제안한다. **제안만** 한다 — 실제 lint 설정·CI·리뷰 기준 반영은 **사용자가 선택**하고 호출자가 수행. **표준 설정을 자동으로 바꾸지 않는다.** 회사·플랫폼 중립이다.

리뷰 라이프사이클의 마지막 단계: "반복 지적 → 강제화"로 **리뷰가 스스로 기준을 강화하는 피드백 루프**. 채택된 결과와 관련 코드는 코드 작성 프로세스로 연결된다.

## 입력 (호출자 제공)
- 일정 기간 누적된 리뷰 지적/댓글 집합 — 접두어(`issue`/`discuss`/`nit`)·내용·위치·대상·빈도를 추출할 수 있는 형태.

## 절차
1. **클러스터링**: 같은 성격의 반복 지적을 묶는다(동일 안티패턴·같은 계약 위반·반복되는 누락 등). 1회성·맥락 특수 지적은 제외.
2. **랭킹**: 빈도 × 영향으로 정렬. **rule-of-three 미만**(1~2회)은 승격 후보에서 보류.
3. **승격 후보 제안** — 클러스터별로 가장 적합한 강제 수단 하나:
   - **기계 검증 가능** → lint/format 규칙 또는 CI 체크(정적 분석·가드).
   - **판단 필요(기계화 어려움)** → 리뷰 기준 항목 추가(`pr-review` 팀 오버레이).
4. **인간 게이트**: 후보를 **근거(대표 사례·빈도·오탐 위험)** 와 함께 제시. **채택 여부는 사용자가 결정.** 채택된 것만 호출자가 반영.

## 대원칙
- **자동 적용 금지.** 항상 제안 → 사용자 선택 → 호출자 반영.
- **반복이 근거일 때만 승격 제안**(rule-of-three).
- 규칙화의 **비용(오탐·개발 마찰)을 이득과 함께 정직하게** 표기 — 오탐 많을 규칙은 그 위험을 명시.
- 과설계 경계: 한두 사례를 위해 광범위한 규칙을 만들지 않는다.

## 출력
승격 후보 목록 — 각 {반복 지적 요약 · 대표 사례 · 빈도 · 제안 강제 수단(lint/CI/기준) · 오탐 위험}. 사용자가 선택하면 호출자가 lint 설정·CI·팀 기준에 반영하고, 관련 코드는 코드 작성 프로세스로 넘긴다.
