# 품질 다이제스트 (반복 발견 사항 → 강제 규칙 제안)

일정 기간 누적된 리뷰 발견 사항을 모아 **반복되는 품질 문제**를 식별하고, **강제 규칙으로 승격**할 후보를 제안한다. **제안만** 한다 — **사용자가** 채택 여부를 선택하고, lint 설정·CI·리뷰 기준에 대한 실제 변경은 호출자가 수행한다. **표준 설정을 자동으로 변경하지 않는다.** 회사·플랫폼 중립을 유지한다.

이는 리뷰 생애주기의 마지막 단계다: "반복 발견 → 강제화"이며, **리뷰가 스스로의 기준을 강화하는 피드백 루프**를 만든다. 채택된 결과와 관련 코드는 코드 작성 프로세스로 흘러들어간다.

## 입력 (호출자 제공)

- 일정 기간 누적된 리뷰 발견 사항이나 코멘트의 집합. 접두사(`issue`/`discuss`/`nit`), 내용, 위치, 대상, 빈도를 추출할 수 있는 형태여야 한다.

## 절차

1. **군집화:** 같은 안티패턴, 반복되는 계약 위반, 반복되는 누락 같은 같은 종류의 반복 발견 사항을 묶는다. 일회성이거나 맥락 의존도가 높은 발견 사항은 제외한다.
2. **순위화:** 빈도 × 영향도로 정렬한다. **삼세번 규칙** 미만(한두 번 발생)은 승격 후보에서 제외한다.
3. **승격 후보 제안:** 각 군집에 가장 적합한 강제 메커니즘 하나를 선택한다:
   - **기계적으로 검증 가능** → 정적 분석이나 가드 같은 lint/포맷 규칙 또는 CI 점검.
   - **판단이 필요하고 자동화가 어려움** → `pr-review` 팀 오버레이에 추가하는 리뷰 기준 항목.
4. **인간 게이트:** 각 후보를 **증거(대표 사례, 빈도, 오탐 위험)**와 함께 제시한다. **채택 여부는 사용자가 결정한다.** 호출자는 채택된 후보만 구현한다.

## 핵심 원칙

- **자동으로 적용하지 않는다.** 항상 제안 → 사용자 선택 → 호출자 구현 순이다.
- 반복이 **증거를 제공할 때만** 승격을 제안한다(삼세번 규칙).
- 강제화의 **비용 — 오탐과 개발 마찰 — 을 이점과 함께 정직하게 보고한다.** 오탐이 많이 발생할 것으로 보이는 규칙은 명시적으로 표시한다.
- 과설계를 경계한다: 한두 사례만으로 광범위한 규칙을 만들지 않는다.

## 출력

승격 후보 목록을 반환한다. 각 항목은 `{ 반복 발견 사항 요약 · 대표 사례 · 빈도 · 제안된 강제 메커니즘(lint/CI/기준) · 오탐 위험 }`을 담는다. 사용자가 선택한 뒤 호출자는 lint 설정, CI, 팀 기준을 업데이트하고 관련 코드 변경을 코드 작성 프로세스로 보낸다.
