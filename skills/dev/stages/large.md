# L Stage — Task Split, Runners, Integration, Final Review

> Read from `SKILL.md` when the size confirms L. Everything in SKILL.md (MUST/NEVER, approval gate, contest, context budget) still applies; this file adds only the L-specific sequence. Workspace runs (multi-repo entry) keep the 0.10 rules: register each repo pre-approval with `execution.mjs repo-add`, every task and `integrationVerification` entry carries its `repo` key, and per-task git operations use that member workroot.

## Sequence

1. **ARCH design + review (only when an ARCH trigger holds)** — triggers: ① new component/module/service ② boundary or cross-module/repo contract change ③ data-ownership or storage choice ④ technology selection ⑤ SPOF/scaling/availability decision. Producer = `harnie-designer` (opus — effort high at hard; `fable` with opus+effort-high fallback at very-hard; per `model-matrix.md` §3's ARCH row; profile path `design-authoring-arch.md`, formal) writing `design/arch-rev-N.md` (new file per revision); reviewer = Codex at the **ARCH altitude** via the DR loop (`review/design-arch/`, artifact `dr:` hash). An unsupported formal architecture stage is scope inflation — skip when the existing architecture holds.
2. **Task-split draft → task-scoped grounding → CONTRACT.** Draft the decomposition, then spawn `harnie-scout`s in parallel per draft task to verify its code paths, existing tests, and runtime/driver·session semantics — the per-task Environment Fact Sheets. Producer = `harnie-designer` (profile `design-authoring-contract.md`) writes `design/contract-rev-N.md` **on that evidence**: decomposition table (independent-review-value rationale per task — the merge-by-default rule lives in the profile), inter-task contracts, fact sheets, verification strategy (automated/human). Reviewer = Codex at the **CONTRACT altitude** (`review/design-contract/`).
3. **Approval (once)** — `plan.md` = CONTRACT summary + manifest block (`gates: [final-review]`, `integrationVerification` required); SKILL.md's approval-gate rules apply (evidence proofs, arm → one-shot AskUserQuestion).
4. **Briefs** — per task `tasks/t<id>-brief.md`: manifest entry + that task's decomposition row, relevant contract sections, and fact sheet (excerpted) + notepad extracts + the `builder-contract.md` path. Reissue as `.vN+1` (new file) when an approved correction touches a cited section.
5. **Execution waves — repeat 5→6 until every task is confirmed.** Each wave: for every task whose deps are **all confirmed** (step 6 done — not merely merged): `set-task … building`, then spawn `harnie-task-runner` (background; unit-review tier as model override) with task id, run workroot, task repo workroot, `<ROOT>`, brief path, builder model, and — on respawn — the bound `builderThreadId`. First-ever runner-path run on an installation: single canary runner first (binding handshake). Collect exit reports into `notepad.md`; triage FAILURE (infra fail-fast → stop spawning, notify, recommend session restart; watchdog deny → one self-extension per task via `watchdog-extend --reason auto-cap`, beyond cap ask the user; STALLED → surface, then `--reentry`; `contract-conflict:` → step 7). Newly-eligible dependents enter the next wave.
6. **Sequential integration, one task at a time** — capture `mergeBaselineSHA` at the task's member workroot, `seal`, `worktree.mjs merge`; conflicts: capture-before-touch, resolve, one CR round on the resolution delta. Then the **confirmation round** (`harnie-reviewer`, confirmation tier, delta from mergeBaselineSHA, prior unit verdict as context — on REJECT, fix through the task's still-live worktree and bound thread, re-merge incrementally, re-review) and that task's `verify --task <id>`. **Only after confirmation APPROVE + verify pass**, remove the worktree with `worktree.mjs remove … --archive-to <repo>` — always archive; never remove earlier. Finish a task's whole integration before the next (seal is run-scoped).
7. **CONTRACT defects in-flight (errata path)** — anyone surfaces the defect; only you register it: `execution.mjs errata-add --root <repo> --slug <slug> --severity <blocker|degrade|note> --design-ref "contract-rev-N §…" --defect "<what+evidence>"`. `note` → `errata-set-disposition --root <repo> --slug <slug> --id E-NNN --disposition <value> --correction <text|@file>` (CLI-only); `blocker`/`degrade` → stop building against the flawed statement, then `errata-arm --root <repo> --slug <slug> --id E-NNN --disposition <approved-workaround|deferred-next-run|superseded-by-A5.2> --correction <text|@file> --approve-option "<label>"` + the very next AskUserQuestion (one-shot binding; exact match). Once approved, propagate by cited section: **unstarted** task → reissue brief `.vN+1` before spawning; **runner in flight** → TaskStop, reissue, respawn (resume-safe); **already integrated** → `rebind-task --task <id> --reason correction:E-NNN` (arms the run-root bootstrap marker) and a serial fix round in the run root, or `--cancel --reason approved-artifact:<postSHA>` if the disk already satisfies it; **deps descendants re-run `verify` only, escalating to fix targets only on failure**. Reissued briefs invalidate the task's design approval mechanically (`dr:` mismatch). Anything touching scope/verification/tasks is `superseded-by-A5.2` — the full manifest re-approval; errata corrects contract prose only. Pending blocker/degrade entries count as completion blockers.
7b. **Post-integration code fixes** (a confirmation REJECT after worktree removal, an integration-verification failure, a Final Review finding): `rebind-task --root <repo> --slug <slug> --task <owning id> --reason <correction:E-NNN | finding:<reviewUnit>:CR-NNN | verification:integration>` — `correction:` when it stems from a contract defect (register the errata first); `finding:` for a pure code defect, naming **the review unit whose ledger raised it plus that CR ID** (unit-scoped — CR IDs repeat across ledgers); `verification:integration` when the integration verification itself failed (no ledger exists there) → capture a recorded baseline in that task's reviewUnit dir → one bootstrap builder call in the run root (the marker binds it) → CR round on the delta → re-run `verify --task`, then `verify --integration` (the old receipt is tree-invalidated), then re-run Final Review if it had approved.
8. **Integration verification** — after all tasks confirm: `verify --integration` (full suite; one passing receipt bound to the final tree; failures → fix through the owning task's thread → rerun).
9. **Final Review (one unit)** — reviewer = `harnie-reviewer` at **opus**, unit `review/final-review/`, whole-tree artifact (`ws:` composite in workspace runs). Four-lens checklist in one pass: coverage (every plan requirement built), quality (full `code-review.md`), runtime (evidence via the integration receipt — **no test re-runs**), scope (nothing unrequested). Tree changes after approval mechanically invalidate it.
10. **Completion** — `execution.mjs completion`; report per-task verdicts/rounds, integration receipt, Final Review verdict, human-verification checklist, errata digest; end with the `HARNIE_STATUS` footer.

## L-specific NEVER

- A task below independent review value in the manifest (merge it — the gate shows the rationale column to the user).
- A "full re-verification" task, or any full-suite run outside step 8.
- Starting a dependent task before its dependency's **confirmation** (not merely merge) approves.
- Serial execution of ≥2 disjoint tasks without a recorded rationale in `notepad.md`.
