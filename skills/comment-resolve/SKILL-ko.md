# 댓글 해결 (검증 판단)

내가 시작한 리뷰 지적 중 **아직 해결되지 않은 스레드**에 대해, 작성자의 응답이 그 지적을 **실제로 해소했는지 검증**하고 resolve/유지/무행동을 판정한다. **판단만** 한다 — 대상 스캔·조회·resolve 실행·투표·대댓글 전송·플랫폼 API·작업목록 관리는 호출자(플랫폼·루틴)가 수행한다. 회사·플랫폼 중립이다.

이건 신규 리뷰가 아니라 **"리뷰 → 작성자 대응 → 해결"** 파이프라인의 해결 단계다. **새 리뷰 지적을 만들지 않는다**(그건 `pr-review`).

## 해소 판정 기준 (pr-review 해제 조건)
- **`issue:`** — 수정 또는 반증으로 해소(코드로 확인 가능).
- **`discuss:`** — 답변·결론으로 해소(코드 변경 없이도 가능).
- **`nit:`** — 선택(반영 강제 아님).

## 대원칙 (안전 핵심)
- **검증 후에만 resolve.** "수정했다"는 주장이나 "푸시됐다"는 사실만으로 닫지 않는다 — 코드·설명·후속을 실제로 확인한다.
- **내가 시작한 스레드만** 판정한다. 타 리뷰어 스레드는 건드리지 않는다.
- **애매하면 무행동이 기본값.** 조금이라도 불확실하면 닫지 않고 유지한다.
- **멱등**: 이미 처리(해결/유지 응답)한 것은 재처리하지 않는다.

## 입력 (호출자 제공)
- 내 미해결 스레드 목록 — 각: 루트 댓글의 접두어(`issue`/`discuss`/`nit`)·내용·위치, 최근 응답과 응답자, 변경 전후 diff 접근 수단.
- 컨텍스트: **진행 중(active)** | **병합됨(merged)**.

## 판정 경로

### 경로 A — 작성자 답변 있음 (최근 응답 = 작성자)
- **코드 수정 주장** → 최신 변경에서 실제 반영을 확인.
- **문서/설명 반영 주장** → 해당 산출물을 확인.
- **단순 설명(코드 불필요)** → 그 설명이 지적에 타당한지 판단.
- **병합됨 컨텍스트**: 코드 수정 주장은 대개 별도 후속 작업을 가리킴 → 그 설명·후속 처리를 확인.

판정: 해소 확인 → **resolve 권고** / 불충분·부적절 → **유지 + 추가 질문 응답 권고** / 애매 → **유지(확인 요청)**.

### 경로 B — 답변 없이 코드만 변경 (active 전용)
최근 응답이 없으면(작성자가 텍스트 없이 코드만 푸시했을 수 있음). **접두어로 판정 가능성 분류** (리뷰어가 밝힌 의도를 재해석하지 않음):
- **게이트**: 내 마지막 코멘트 이후, 그 변경이 **내 지적 파일을 실제로 건드렸을 때**만 경로 B 대상. 아니면 건너뜀(작성자 대기).
- **`issue:`** → 판정 가능: 변경 코드가 지적을 **명확히** 해소했으면 근거를 남긴 뒤 **resolve 권고**. 미해소·부분·애매 → **무행동**(다음 변경 대기).
- **`discuss:`** → 판정 불가: 코드만으론 확신 불가(의도·도메인·런타임 근거 필요) → **무행동**(답변 대기). 새 대댓글도 만들지 않는다.

## 재투표 권고 (active 전용 — 호출자가 실행)
이번에 스레드 상태가 실제로 바뀐 경우에만:
- 미해결 `issue:`/`discuss:` 없음 → **승인 권고**
- `issue:`/`discuss:` 미해결 남음 → **보류(투표 변경 없음)**
- 남은 미해결이 `nit:`뿐 → **조건부 승인 권고**

병합됨 컨텍스트는 **투표하지 않는다**(무의미).

## 출력 언어
- 사람이 읽는 판정·사유·근거 요약·추가 질문 권고·재투표 권고는 모두 **한국어로 작성한다.**
- 기계 판독용 상태값·코드 식별자·파일 경로·API 이름·인용한 원문은 원래 표기를 유지한다.

## 출력
스레드별 판정: `resolve` | `유지(+사유)` | `무행동`, 그리고 (active면) 재투표 권고. 실제 resolve·대댓글·투표·플랫폼 호출은 호출자가 이 판정을 받아 수행한다.

> `pr-review`와 별개다: `pr-review`=신규 변경 평가(무엇이 문제인가), `comment-resolve`=그 지적에 대한 응답이 문제를 해소했는가(검증). 개발 중 in-loop 리뷰(REJECT-bias, `instructions/`)와도 별개.
