# 코멘트 해결 (검증 판단)

내가 시작한 리뷰 발견 중 **해결되지 않은 스레드**에 대해, 작성자의 응답이 그 발견을 **실제로 해결하는지** 검증하고 resolve할지, 열어둘지, 아무 조치도 하지 않을지 결정한다. **판단만** 한다 — 대상 스캔, 조회, resolve, 투표, 후속 답글, 플랫폼 API, 작업 목록 관리는 호출자(플랫폼 또는 루틴)가 처리한다. 회사·플랫폼에 중립을 유지한다.

이것은 새로운 리뷰가 아니다. **"리뷰 → 작성자 응답 → 해결"** 파이프라인의 해결 단계다. **새로운 리뷰 발견을 만들지 않는다.** 그것은 `pr-review`의 몫이다.

## 해결 기준 (`pr-review` 언블로킹 조건)

- **`issue:`** — 코드로 검증할 수 있는 수정이나 반박으로 해결한다.
- **`discuss:`** — 답변이나 결론으로 해결한다. 코드 변경은 필요하지 않다.
- **`nit:`** — 선택 사항이다. 구현은 필수가 아니다.

## 핵심 원칙 (안전 필수)

- **검증 후에만 resolve한다.** 누군가 수정했다고 주장하거나 push가 있었다는 이유만으로 스레드를 닫지 않는다. 코드, 설명, 후속 조치를 직접 확인한다.
- **내가 시작한 스레드만** 판단한다. 다른 리뷰어의 스레드는 건드리지 않는다.
- **불확실하면 기본값은 아무 조치도 하지 않는 것이다.** 조금이라도 불명확한 부분이 남아 있으면 스레드를 열어둔다.
- **멱등하게 처리한다:** 이미 resolve 또는 열어두기로 응답한 항목은 다시 처리하지 않는다.

## 입력 (호출자가 제공)

- 내가 남긴, 해결되지 않은 스레드 목록. 각 항목은 루트 코멘트의 접두어(`issue`/`discuss`/`nit`), 내용, 위치, 최신 응답과 응답자, 변경 전후 diff에 접근하는 방법을 포함한다.
- 컨텍스트: **active** | **merged**.

## 판단 경로

### 경로 A — 작성자가 답글을 남긴 경우 (최신 응답이 작성자)

- **코드 수정을 주장** → 최신 변경에서 확인한다.
- **문서/설명 업데이트를 주장** → 관련 산출물을 확인한다.
- **설명만 제공(코드 불필요)** → 그 설명이 발견 사항을 충분히 다루는지 판단한다.
- **merged 컨텍스트:** 코드 수정을 주장하는 경우 보통 별도의 후속 작업을 가리킨다 → 설명과 후속 처리를 확인한다.

판단: 해결이 확인되면 → **resolve 권고** / 응답이 불충분하거나 부적절하면 → **열어두기 + 후속 질문 권고** / 모호하면 → **열어두기(확인 요청)**.

### 경로 B — 답글 없이 코드만 변경된 경우 (active 전용)

최신 응답이 없을 수 있다. 작성자가 텍스트 없이 코드만 push했기 때문이다. 판단이 가능한지는 **접두어**로 분류한다. 리뷰어가 명시한 의도를 재해석하지 않는다.

- **게이트:** 내 마지막 코멘트 이후의 변경이 **내 발견에서 지목한 파일을 실제로 건드릴 때만** 경로 B를 고려한다. 그렇지 않으면 건너뛰고 작성자를 기다린다.
- **`issue:`** → 판단이 가능하다. 변경된 코드가 발견 사항을 **명확하게** 해결하면 근거를 기록하고 **resolve를 권고**한다. 해결되지 않았거나, 부분적이거나, 모호하면 **아무 조치도 하지 않고** 다음 변경을 기다린다.
- **`discuss:`** → 코드만으로는 판단할 수 없다. 의도, 도메인 맥락, 런타임 근거가 필요하기 때문이다. **아무 조치도 하지 않고** 답글을 기다리며, 새 후속 코멘트를 추가하지 않는다.

## 재투표 권고 (active 전용, 호출자가 실행)

이번 실행에서 스레드 상태가 실제로 바뀌었을 때만 재투표를 권고한다.

- 해결되지 않은 `issue:`나 `discuss:`가 남아 있지 않으면 → **승인 권고**.
- 해결되지 않은 `issue:`나 `discuss:`가 남아 있으면 → **보류, 투표를 바꾸지 않는다**.
- 해결되지 않은 `nit:` 스레드만 남아 있으면 → **조건부 승인 권고**.

merged 컨텍스트에서는 **투표하지 않는다**. 효과가 없기 때문이다.

## 출력 언어

- 사람이 읽는 판단, 이유, 근거 요약, 후속 질문 권고, 재투표 권고는 모두 **한국어로** 작성한다.
- 기계가 읽는 상태 값, 코드 식별자, 파일 경로, API 이름, 인용한 소스 텍스트는 원문 그대로 유지한다.

## 출력

각 스레드에 대해 `resolve` | `keep open (+ reason)` | `no action` 중 하나를 반환하고, 컨텍스트가 active면 재투표 권고를 덧붙인다. 호출자는 이 판단을 사용해 실제 resolve, 후속 답글, 투표, 플랫폼 호출을 수행한다.

> 이것은 `pr-review`와 다르다. `pr-review`는 새 변경을 평가하고 문제를 찾아내며, `comment-resolve`는 보고된 문제에 대한 응답이 실제로 해결됐는지 검증한다. 설계 대비 구현 리뷰(`implementation-review` 스킬)와도 다르다.
