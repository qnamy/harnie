# 배포 승인 (게이트 판정)

배포 승인 요청에 대해 **대상 변경 사항을 검토**하고, **어떤 문제가 배포를 막아야 하는지**에 따라 승인 또는 보류를 판정한다. **판정만** 한다 — 호출자(플랫폼 또는 루틴)가 리액션이나 투표 같은 승인 신호를 기록하고, 정족수를 집계하고, 티켓 같은 워크플로 상태를 전이한다. 회사·플랫폼 중립을 유지한다.

## 검토 기준 (`pr-review`)

배포 게이트는 **차단 문제만** 고려한다: `pr-review`의 **`issue:` 수준**에 해당하는 우려, 즉 정확성·안전성·로직 오류·breaking change다. `discuss:`와 `nit:` 수준 우려는 배포를 막지 않으며, 별도 리뷰 트랙에서 처리한다.

## 핵심 원칙 (안전 최우선)

- **확신이 낮으면 보류한다.** 잘못된 배포 승인은 지연보다 훨씬 나쁘다.
- **검토 후에만 승인한다.** 요청이 존재한다는 이유만으로 승인하지 않는다.
- **대상 변경 사항을 식별할 수 없으면 승인하지 않고, 수동 검증을 위해 보류한다.**
- **멱등성을 지킨다:** 이미 승인 신호가 있거나 보류 사유가 기록된 요청은 재처리하지 않는다.

## 입력 (호출자 제공)

- 승인 요청과 대상 변경 사항(PR/diff)에 접근할 방법.
- 선택 사항으로 현재 승인 수, 정족수 임계값, 티켓 같은 연결된 워크플로 상태.

## 판정

1. **대상 변경 사항을 식별한다.** 식별할 수 없으면 "대상 미식별, 수동 검증 필요"라는 사유로 **보류**한다.
2. `pr-review` 기준으로 **`issue:` 수준 문제**를 검토한다:
   - 발견됨 → **보류**하고 문제를 요약한다.
   - 없음 → **승인**한다. 승인 신호는 호출자가 기록한다.
3. 호출자가 제공한 수치로 **정족수를 확인한다**. 승인 수가 임계값 이상이면 **워크플로 상태 진행을 권고**한다. 그렇지 않으면 진행하지 않고 다음 승인자를 기다린다.
   - 항목이 이미 목표 상태이거나 그 이후 상태면 멱등성을 위해 진행을 건너뛴다. 목표 상태로의 직접 전이가 불가능하면 진행을 보류하고 수동 검증으로 넘긴다.

## 출력 언어

- 사람이 읽는 승인 판정, 보류 사유, 문제 요약, 정족수 권고, 수동 검증 안내는 모두 **한국어로** 작성한다.
- 기계가 읽는 상태값, 코드 식별자, 파일 경로, API 이름, 인용된 원문은 원형 그대로 보존한다.

## 출력

요청마다 `approve`(정족수 충족 시 워크플로 진행 권고 포함) 또는 `hold (+ 사유)`를 반환한다. 호출자는 이 판정을 사용해 승인 신호를 기록하고, 정족수를 집계하고, 상태를 전이하고, 필요하면 수동 검증 알림을 보낸다.

> 배포 게이트에는 `pr-review` 판정의 축소판을 적용한다: 차단 문제만. 이는 설계 대비 구현 리뷰(`implementation-review` 스킬)와는 별개다.
