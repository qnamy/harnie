# 배포 승인 (게이트 판단)

배포 승인 요청에 대해 **대상 변경을 검토**하고 **배포를 막을 문제가 있는지**로 승인/보류를 판정한다. **판단만** 한다 — 승인 신호(반응·투표) 표시, 정족수 집계, 워크플로 상태(티켓 등) 전환은 호출자(플랫폼·루틴)가 수행. 회사·플랫폼 중립이다.

## 검토 기준 (pr-review)
배포 게이트는 **차단 문제만** 본다 = `pr-review`의 **`issue:` 급**(정확성·안전성·로직 오류·파괴적 변경). `discuss:`/`nit:` 급은 배포를 막지 않는다(별도 리뷰 트랙에서 다룸).

## 대원칙 (안전 핵심)
- **확신이 낮으면 보류.** 잘못된 배포 승인은 지연보다 훨씬 나쁘다.
- **검토 후에만 승인.** 요청이 올라왔다는 사실만으로 승인하지 않는다.
- **대상 변경을 특정하지 못하면 승인하지 않고 보류**(수동 확인 요청).
- **멱등**: 이미 처리(승인 신호 또는 보류 사유 기록)한 요청은 재처리하지 않는다.

## 입력 (호출자 제공)
- 승인 요청 + 대상 변경(PR/diff) 접근 수단.
- (선택) 현재 승인 수·정족수 임계값·연결된 워크플로 상태(티켓 등).

## 판정
1. **대상 변경 특정** — 못 하면 **보류**(사유: 대상 미특정, 수동 확인).
2. `pr-review` 기준으로 **`issue:` 급 문제** 검토:
   - 있음 → **보류** + 발견 이슈 요약.
   - 없음 → **승인** (호출자가 승인 신호 표시).
3. **정족수 확인**(호출자 제공 카운트): 승인 수 ≥ 임계값 → **워크플로 상태 전진 권고**. 미달 → 전진하지 않음(다음 승인자 대기).
   - 이미 목표 상태이거나 그 이후면 전진 스킵(멱등). 목표 상태로 직접 전이가 불가하면 전진 보류(수동 확인).

## 출력
요청별 판정: `승인`(+정족수 도달 시 상태 전진 권고) | `보류(+사유)`. 실제 승인 신호·정족수 집계·상태 전환·수동확인 알림은 호출자가 이 판정을 받아 수행한다.

> `pr-review`의 판단을 배포 게이트 용도로 좁혀 쓴다(차단 문제만). 개발 중 in-loop 리뷰(`instructions/`)와는 별개다.
