# PR 전달 (PR 본문과 리뷰 요청 콘텐츠)

완료된 변경 사항을 전달하는 산출물의 **콘텐츠(무엇을)**를 작성한다: PR 제목과 본문, 그리고 리뷰 요청 메시지. **작성과 판단만** 수행한다. 회사·플랫폼 중립을 유지한다.

이는 빌드 프로세스의 마지막 단계다(... → 개발 리뷰 → **PR 생성 → 리뷰 요청**). 결과 PR은 이후 상대방의 `pr-review`에 입력이 된다.

## 입력 (호출자 제공)

- 변경 사항(diff/커밋), 빌드 맥락(해결한 문제, 핵심 설계 결정, 실제로 수집한 검증 증거), 그리고 선택적으로 연결된 이슈나 티켓.
- 다음을 정의하는 **Delivery Profile**:
  - **제목 규칙:** 예를 들어 티켓 접두사 방식 또는 평문 방식.
  - **본문 섹션 집합:** 아래 섹션 라이브러리에서 선택된 부분집합.
  - **리뷰 요청 정책:** `none` 또는 `ask-once-then-send`.
- 선택 사항으로 표준·고정밀·보안·성능 같은 요청 유형 또는 리뷰 렌즈.

## Delivery Profile (호출자가 주입)

이 스킬에 환경별 규칙을 내장하지 않고 호출자가 제공한 프로필을 적용한다.

- 프로필의 제목 규칙에 따라 제목 형식을 만든다.
- 프로필이 선택한 본문 섹션만 포함하며, 순서가 지정되어 있으면 그 순서를 따른다.
- `none`이면 호출자가 초안 전용 콘텐츠를 명시적으로 요청하지 않는 한 리뷰 요청 발송을 위한 콘텐츠를 만들지 않는다.
- `ask-once-then-send`면 상위 단계에서 이미 승인을 받았다면 확인 프롬프트를 다시 만들지 않는다. 즉시 발송 가능한 최종 메시지를 만든다.
- 브랜치와 머지 전략, 그리고 모든 실행 세부사항은 호출자의 **어떻게**로 취급한다.

## PR 본문 섹션 라이브러리

- **배경:** 변경이 왜 필요한지를 설명한다: 문제와 의도.
- **변경 사항:** 무엇이 어떻게 바뀌었는지 설명한다. 유용할 때는 리뷰어가 살펴봐야 할 주요 영역을 짚는다.
- **리뷰 포커스:** 눈에 띄지 않는 결정과 트레이드오프를 포함해 리뷰어가 주의를 기울여야 할 영역을 알려준다.
- **검증:** 실제로 실행한 점검과 그 결과만 나열한다. 검증하지 않은 부분은 명확히 밝히고 과장하지 않는다.
- **범위와 비목표:** 포함된 것과 의도적으로 제외한 것을 명시한다. 연결된 이슈나 티켓이 제공되면 포함한다.

Delivery Profile은 이 섹션들 중 부분집합을 선택한다. 흔한 원형은 다음과 같다:

- **full:** 배경, 변경 사항, 리뷰 포커스, 검증, 범위와 비목표.
- **minimal:** 변경 사항만.

변경 사항과 제공된 맥락으로 뒷받침되는 사실만 서술한다. 빠진 사실을 지어내거나 추측하지 않으며, 불확실성은 명시적으로 남긴다.

## 리뷰 요청 콘텐츠

- 호출자가 실제 URL을 구성할 경우를 대비해 PR 참조 자리표시자와 무엇을 어디서 리뷰할지를 포함한다.
- 리뷰에 필요한 맥락만 제공한다: 핵심 결정, 트레이드오프, 주의가 필요한 영역.
- 리뷰 유형이나 요청된 렌즈를 명시한다.
- 최종 메시지는 간결하게 유지하고 호출자가 설정한 승인 정책에 맞춰 즉시 발송 가능하게 한다.

## 실행은 호출자 소관이다

호출자가 **어떻게**를 소유한다: PR 생성 메커니즘, 플랫폼 좌표, 대상 브랜치, 브랜치와 머지 전략, 리뷰어 지정, 리뷰 요청 대상, 멘션, 실제 발송. 이 값들은 호출자의 해당 지침이나 설정에서 읽는다. 이 스킬은 이를 알지 못한다.

## 출력

주입된 Delivery Profile을 반영해 `{ PR 제목, PR 본문(Markdown), 리뷰 요청 메시지 콘텐츠, 리뷰 유형 }`을 반환한다. 프로필이 리뷰 요청을 선택하지 않으면 발송 가능한 리뷰 요청 콘텐츠를 반환하지 않는다. 호출자는 이 결과로 PR을 생성하고, 해당하면 리뷰 요청을 보낸다.
