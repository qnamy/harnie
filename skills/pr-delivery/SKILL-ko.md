# PR 전달 (PR 본문 · 리뷰요청 내용)

완성된 변경을 전달하는 산출물의 **내용(무엇)** 을 작성한다: PR 제목·본문과 리뷰요청 메시지. **작성·판단만** 수행한다. 회사·플랫폼 중립을 유지한다.

빌드 프로세스의 마지막 단계(… → 개발리뷰 → **PR 생성 → 리뷰요청**)다. 산출된 PR은 이후 상대의 `pr-review` 입력이 된다.

## 입력 (호출자 제공)

- 변경(diff/커밋), 빌드 맥락(해결한 문제·핵심 설계 결정·실제로 수집한 검증 증거), 선택적 연결 이슈 또는 티켓.
- 다음을 정의하는 **Delivery Profile**:
  - **제목 규약:** 예를 들어 티켓 접두형 또는 일반형.
  - **본문 섹션 집합:** 아래 Section Library에서 선택한 부분집합.
  - **리뷰요청 정책:** `none` 또는 `ask-once-then-send`.
- 선택적 요청 종류 또는 리뷰 관점(예: 일반, 고정밀, 보안, 성능).

## Delivery Profile (호출자 주입)

이 스킬에 환경 고유 규약을 넣지 말고 호출자가 제공한 프로필을 적용한다.

- 프로필의 제목 규약에 따라 제목을 작성한다.
- 프로필이 선택한 본문 섹션만 포함하며, 호출자가 순서를 지정하면 그 순서를 따른다.
- `none`이면 호출자가 초안만 명시적으로 요청한 경우를 제외하고 전송용 리뷰요청 내용을 만들지 않는다.
- `ask-once-then-send`이고 상류에서 이미 승인을 받았다면 확인 질문을 다시 만들지 않는다. 즉시 전송 가능한 최종 메시지를 산출한다.
- 브랜치·merge 전략을 포함한 모든 실행 세부사항은 호출자의 **어떻게**로 취급한다.

## PR 본문 Section Library

- **배경(Background):** 변경이 필요한 이유, 즉 문제와 의도를 설명한다.
- **변경사항(Changes):** 무엇이 어떻게 바뀌었는지 설명한다. 유용한 경우 리뷰어가 확인할 주요 영역을 짚는다.
- **리뷰 초점(Review focus):** 리뷰어가 집중할 지점, 비자명한 결정, 트레이드오프를 제시한다.
- **검증(Verification):** 실제로 수행한 검사와 결과만 나열한다. 검증하지 않은 것은 명확히 밝히며 꾸미지 않는다.
- **범위·비목표(Scope & non-goals):** 포함한 것과 의도적으로 제외한 것을 밝힌다. 제공된 연결 이슈나 티켓을 포함한다.

Delivery Profile은 이 섹션들의 부분집합을 선택한다. 일반적인 아키타입:

- **full:** 배경, 변경사항, 리뷰 초점, 검증, 범위·비목표 전체.
- **minimal:** 변경사항만.

변경과 제공된 맥락으로 뒷받침되는 사실만 쓴다. 없는 사실을 지어내거나 추측하지 않고 불확실성은 명시한다.

## 리뷰요청 내용

- 호출자가 실제 URL을 구성한다면 PR 참조 자리표시자와 함께 무엇을·어디를 리뷰할지 포함한다.
- 핵심 결정·트레이드오프·주의할 지점 등 리뷰에 필요한 맥락만 제공한다.
- 리뷰 종류 또는 요청 관점을 명시한다.
- 호출자가 설정한 승인 정책에 맞춰 최종 메시지를 간결하고 바로 사용할 수 있게 작성한다.

## 실행은 호출자 소관

PR 생성 방식·플랫폼 좌표·대상 브랜치·브랜치와 merge 전략·리뷰어 지정·리뷰요청 목적지·멘션·실제 전송 등 **어떻게**는 호출자 소관이다. 호출자에게 적용되는 지침이나 설정에서 해당 값을 읽는다. 이 스킬은 그 좌표를 모른다.

## 출력

주입된 Delivery Profile을 반영해 `{ PR 제목, PR 본문(마크다운), 리뷰요청 메시지 내용, 리뷰 종류 }`를 반환한다. 프로필이 리뷰요청을 선택하지 않으면 전송 가능한 리뷰요청 내용을 반환하지 않는다. 호출자는 결과를 사용해 PR을 생성하고, 해당하는 경우 리뷰요청을 전송한다.
