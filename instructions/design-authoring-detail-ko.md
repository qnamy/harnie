# 설계 작성 프로필 — TASK-DETAIL 고도 (canonical, 주입용)

**확정된 경계 안의 상세 설계** 출력 계약: M run의 단일 유닛, 또는 임의의 독립 상세 설계. 호출자가 이 파일의 절대 경로를 전달하고, 저자는 쓰기 전에 이를 Read한다.

**고도**: 확정된 계약을 구현 가능한 코드 수준 결정으로 번역한다 — 구현자가 **추가 핵심 결정 없이** 시작할 만큼 구체적으로, 불필요한 클래스나 패턴 없이.

**부모를 존중한다.** 부모 아키텍처의 이름·소유권·인터페이스를 정확히 보존한다; 절대 무음으로 바꾸지 않는다 — 필요한 변경은 A5.2 재승인 경로로 에스컬레이션하지, 우회 설계하지 않는다. 대상이 한 문서에 담기에 너무 크면 먼저 분해를 제안한다.

## 환경 사실 먼저

결정이 딛고 선 사실들로 문서를 연다 — **각각 실제 레포에서 검증하고 출처 경로를 인용한다** — 잘못된 전제는 낭비되는 리뷰 라운드의 최대 원천이다. 호출자가 제공한 fact sheet(run의 grounding 산출물)를 재도출하지 말고 재사용·검증한다; 네 자신의 패스는 **증분**이다 — 주어진 사실을 검증하고, 공백만 채운다. 해당될 때 커버: 스키마 마이그레이션 head; 테스트 인프라와 baseline 실패; 런타임 설정 한계; 프레임워크/빌드 동작; **드라이버·세션 시맨틱**(batch-scoped SET 옵션, datetime 정밀도 절삭, batch 하의 rowcount 신뢰성 등 스코프 내 구체 드라이버의 함정). 검증 불가능한 사실 위의 결정은 추측이 아니라 `[UNRESOLVED]`다.

## 섹션 (경량 — 작은 작업이면 몇 줄로 압축)

1. **설계 요약** — 대상, 책임, 부모 계약에서의 위치, 입력/출력/의존성, 범위와 비범위.
2. **핵심 처리 로직** — 자명하지 않은 경우만: 전제조건 → 단계(도움이 되면 의사코드) → 성공 후 상태 → 실패별 상태와 보상 → 중복/동시성.
3. **계약** — 자명하지 않은 API/이벤트만: 목적, 인증, 요청/응답 의도, 오류 계약, 멱등성. 기계 판독 스키마는 파일과 ID로 참조.
4. **데이터와 상태** — 변경되는 엔티티, 트랜잭션 경계, 근거를 갖춘 동시성 제어, 핵심 전이.
5. **테스트** — 이 설계를 증명하는 것을 그 위험에 매핑; scope-test 세트 추가분을 명명.
6. **미해결 / 에스컬레이션** — `[UNRESOLVED]` 항목과 contract 또는 아키텍처 변경이 필요한 것.

요구사항 커버리지는 리뷰어가 렌즈로 판정한다; 추적성 매트릭스나 강제 FR/NFR ID 체계는 요구되지 **않는다** — 식별자는 진정 도움이 되는 곳에서만 쓴다.

## NEVER

- 투기적 요소: 근거 없는 인덱스, 캐시, 추상화, 단일 사용 사례의 일반화.
- 장황함 자체를 위한 섹션; 부모 계약이나 이 프로필의 재서술.
- happy path만의 설계 — 오류, 중복, 지연, 재시도, 취소, 동시성은 설계의 일부다.
