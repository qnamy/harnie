# 설계 작성 프로필 — 아키텍처 고도 (canonical, 주입용)

`harnie-designer`가 **아키텍처 설계**를 산출할 때의 **출력 계약**이다. 오케스트레이터가 이 파일의 **절대 경로를 위임 프롬프트에 전달**한다; designer는 **반드시 먼저 이 파일을 Read**해야 한다(에이전트 body는 페르소나·시작 게이트·작업 원칙만 소유 — 여기서 재서술하지 않는다).

**고도**: 시스템 경계와 변경 비용이 큰 기술 결정. 클래스·함수·상세 SQL·전체 API 스키마 같은 **구현 수준으로 내려가지 않는다**(그건 상세 프로필).

**모드 스위치**: 기본 = **경량**(§경량 출력만). 호출자가 **"정식으로"** 신호할 때만 §정식 출력(전체 섹션). 두 모드 모두 body의 깊이 차등·투기 금지·중복 억제·계약 단일 출처를 적용한다.

## §경량 출력 (기본)
1. **Executive Summary** — 비기술 이해관계자용 문제·제안 요약, 핵심 설계 결정 3~5개, 가장 큰 위험 3개. 추적 필요 시 선택적으로 `DEC-001` ID.
2. **목표·범위·비목표·제약** — 성공 지표 포함.
3. **핵심 요구사항** — 중요한 FR/NFR만 `FR-001`/`NFR-001` ID. NFR은 가능하면 수치화(SLO·latency·동시성·데이터 증가/보존·RTO/RPO·비용 한도).
4. **아키텍처 대안 비교** — 2개 이상. 구조·요구충족·복잡도·운영부담·장애격리·성능·비용·벤더종속 표 + 각 대안 적합 조건. **결론을 미리 암시하지 않는다.**
5. **권장 아키텍처** — 선택 근거 + C4 Container 수준 Mermaid(화살표에 프로토콜·데이터·목적), 각 컨테이너 단일 책임, 데이터 소유권, 동기/비동기 통신.
6. **핵심 시나리오** — 정상 흐름 1 + 대표 실패 흐름 1~2(외부 연동 실패·타임아웃·부분 장애)를 Mermaid sequenceDiagram.
7. **리스크·미결정** — 리스크(가능성·영향·완화·결정 기한) + `[미결정]` 목록.

(작은 작업이면 이 계약을 몇 줄로 압축 — 장황한 섹션 강제 아님.)

## §정식 출력 ("정식으로" 요청 시)
경량 출력을 아래 전체 섹션으로 확장한다(깊이 차등·중복 억제 그대로).
1. Executive Summary
2. 목표와 범위 (목표·성공지표·범위·명시적 비목표·제약·용어)
3. 요구사항 — FR(`FR-001`) / NFR(`NFR-001`, 수치화: 가용성·SLO / 응답시간·처리량 / 동시 사용자 / 데이터 증가·보존 / RTO·RPO / 보안·개인정보 / 비용 한도 / 확장 목표) / 우선순위·충돌
4. 시스템 컨텍스트 — 사용자·외부 시스템·책임·신뢰 경계 + C4 System Context (Mermaid)
5. 아키텍처 대안 — 표 비교(구조·요구충족·복잡도·운영부담·장애격리·성능/확장성·보안·비용·벤더종속·장단점·적합 조건)
6. 권장 아키텍처 — 근거 + C4 Container (Mermaid), 컨테이너 단일 책임, 동기/비동기 통신, 데이터 저장소·소유권, 외부 연동, 기술·버전 원칙, 피할 순환 의존성
7. 핵심 시나리오 — 정상 + 실패(외부 연동 실패·중복 요청·부분 장애·타임아웃/재시도) Mermaid sequenceDiagram
8. 데이터 아키텍처 — 데이터 분류·소유권, 저장/조회/보존/삭제, 정합성 모델, 트랜잭션 경계, 캐시 전략, 백업·복구, 개인정보. **상세 테이블 정의·전체 DDL은 쓰지 않는다.**
9. 품질속성 검토 — 운영/보안·개인정보·규정/신뢰성·복구/성능/비용/지속가능성 각각 "설계 선택 → 근거 → 검증 방법 → 잔여 위험". **특정 클라우드 프레임워크에 종속되지 않는 일반 원칙.**
10. 신뢰성·운영 — SLI/SLO 후보, 장애 모드, 타임아웃·재시도·백오프·서킷브레이커, 용량 산정·피크 대응, 로그·메트릭·트레이싱, 알림 기준, 배포·롤백·DR, 운영자 개입 지점
11. 보안·위협 — 주요 자산, 인증·인가, 신뢰 경계, 최소 권한, 암호화·키 관리, 감사 로그, 주요 위협·완화, 오남용 시나리오
12. 배포·마이그레이션 — 배포 토폴로지, 단계적 출시, 하위 호환성, 데이터 마이그레이션, 롤백 조건, 기존 시스템 공존
13. 검증 계획 — FR/NFR ↔ 테스트/부하/장애주입/보안검토/운영리허설 표
14. 리스크·미결정 — 리스크(가능성·영향·완화·담당·결정 기한) + `[미결정]`
15. ADR — 중요 결정마다(제목·상태·맥락·검토 대안·결정·트레이드오프·재검토 조건)
16. 상세 설계로 전달할 항목 — 컴포넌트별 상세에서 정의할 API·데이터·상태·오류·동시성·테스트 목록
